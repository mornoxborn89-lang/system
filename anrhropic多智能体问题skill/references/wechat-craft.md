# AI 漫剧公众号文章写法

## 先决定文章在回答什么

一篇文章保留一个主问题。下面几种主干可以借用，不能机械拼接。

- 产品变化型。从某项新能力进入，解释它改变了创作流程中的哪一步，又把问题推向哪里。
- 流程拆解型。跟随一部作品或一个团队，从剧本走到发布，比较 AI 前后的时间、成本和返工。
- 平台商业型。从平台动作或财报进入，说明平台为什么需要漫剧供给，以及收入和治理如何相互牵制。
- 用户体验型。从观看中的具体感受或数据进入，讨论一致性、节奏、审美和追更动力。
- 产品设计型。把创作者的一项高频任务拆开，说明工具应当如何设计，成功指标是什么。

## 标题

标题承诺正文能回答的内容。优先放入对象、变化和判断，少用夸张词。

可采用这些关系。

- 当某项能力发生变化，谁的工作跟着变了
- 一个具体产品动作透露了什么
- 从一个项目的时间与返工看行业问题
- 观众开始遇到某种体验后，平台需要解决什么

避免“震惊”“颠覆”“彻底改变”“普通人都能赚到钱”等无法负责的承诺。用户没有指定时，内部比较三至五个标题，只交最贴合正文的一个。

## 开头

前三段完成两件事，给出一件具体材料，并说明作者为什么关心它。材料可以是产品界面变化、创作过程、作品、公开数字或平台动作。

不要从“随着人工智能快速发展”写起。不要用一串问题制造紧张感。不要先总结全文结构。

## 正文推进

每个主要部分写清三件事。

1. 发生了什么，谁做了什么。
2. 它改变了流程或关系中的哪一步。
3. 这件事让产品判断发生了什么变化。

材料与判断尽量靠近。事实来自公司口径时保留来源身份。面对不确定之处，直接写范围和疑点。

产品经理术语只有在帮助理解时才出现。常见改写如下。

| 汇报写法 | 公众号写法 |
| --- | --- |
| 降本增效 | 原来几个人做几天，现在哪几步缩短了，返工增加在哪里 |
| 提升一致性 | 同一角色换镜头后，脸、服装和体型能否保持 |
| 工作流闭环 | 创作者从剧本开始，在哪一步得到可发布成片 |
| 赋能创作者 | 创作者以前做不了什么，现在能独立完成哪一步 |
| 商业化能力 | 平台或团队通过什么方式收钱，谁愿意付钱 |

## 速度与成本

AI 漫剧文章经常在速度上失真。区分以下时间。

- 单次图片或视频生成时间。
- 一个镜头得到可用结果的总时间。
- 一集从剧本到成片的时间。
- 一个项目从立项到上线的时间。

同时区分模型费用、算力或积分、人工时间、版权、后期、投流和返工。比较前后效率时保持作品长度与质量目标尽量一致。

## 语言

- 用普通现代汉语，句子先出现主语和动作。
- 允许判断和情绪，不表演网络口吻。
- 不编深夜办公室、创作者神态、天气和对白等假现场。
- 少用“赋能、重塑、颠覆、底层逻辑、时代浪潮、生态闭环、重新定义”。能给动作和数字时直接给。
- 避免“不是……而是……”“你以为……其实……”等先制造误解再翻案的句式。
- 避免三项以上整齐排比。材料已经说明问题时不再补一句空泛升华。
- 结尾给出边界清楚的判断或尚待验证的问题，不重新摘要全文。

## 图片

每张图必须承担一种任务。

- 展示产品输入与输出。
- 解释生产流程或角色关系。
- 对比 AI 介入前后的具体步骤。
- 展示作品中与正文有关的视觉问题。
- 呈现可核验数据。

产品截图注明产品、版本或访问日期。作品画面确认引用与版权边界。生成示意图在图注写“AI 生成示意图”，不把它当作真实产品或作品截图。

## 默认包装

用户要完整公众号稿且未另行指定时，交付以下内容。

1. 一个主标题。
2. 一段六十至一百二十字摘要。
3. 正文。
4. 三至六个对结论重要的来源。
5. 用户要求配图时，把图片与图注放进正文对应位置。

正文长度由材料决定。通常一千五百至二千五百字足以讲清一个产品问题。材料不足时缩短，不重复解释补字数。

## 改稿顺序

1. 删除无法核验的数字、引语和案例。
2. 检查主旨是否被每一部分推进。
3. 补齐从产品能力到用户或商业结果之间缺失的因果步骤。
4. 删除重复段落、宣传口径和模型腔。
5. 调整标题、摘要、小标题、配图和图注。

内容判断优先于格式细节。格式已经清楚可读时，不为追求整齐破坏文章节奏。
